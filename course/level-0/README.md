# Блок 0. Введение и настройка инструментов

Добро пожаловать в курс «AI-инженер на практике: от кастомных MCP до терминального оркестратора». Этот блок — твой пропуск в мир AI-агентов, где LLM не просто болтает, а выполняет реальные задачи: проектирует детали в Компас-3D и отправляет их на лазерную гравировку. Мы начинаем с нуля: разберём архитектуру, поставим инструменты и впервые пообщаемся с моделями DeepSeek и YandexGPT через оркестратор OpenCode. Поехали!

## Модуль 0.1 — Цели курса и обзор архитектуры

### 1.1 Теория: какую проблему решаем и из чего состоит система

**Проблема:** инженеру или производителю нужно быстро превратить идею в готовое изделие. Обычно это цепочка «спроектировал в CAD → экспортировал → передал на станок». Но что, если ты можешь написать текстом «сделай мне прямоугольную пластину с отверстиями по углам» и получить готовый файл для лазерного гравировщика? Именно это мы автоматизируем с помощью AI-агентов.

**Архитектура системы (три ключевых компонента):**

1. **Кастомные MCP-серверы**  
   - **Компас-3D MCP-сервер** — управляет российской CAD-системой КОМПАС-3D: создаёт эскизы, выдавливает 3D-модели, экспортирует DXF.  
   - **CarverAll 15Pro MCP-сервер** — общается с лазерным гравировщиком CarverAll: отправляет файл на резку, следит за статусом, возвращает результат.

2. **Терминальный оркестратор OpenCode**  
   Твой «командир» в мире AI. Он принимает задачу на естественном языке, планирует действия, вызывает нужные MCP-инструменты и следит за результатом.

3. **Большая языковая модель (LLM)**  
   Понимает твои запросы, решает, какие инструменты нужны, и генерирует корректные вызовы. Мы используем open-source модели: DeepSeek-V3 и YandexGPT.

**Как это работает в типичном сценарии:**
```
Ты: «Создай квадратную заготовку 100x100 мм с отверстием 10 мм по центру и вырежи её на гравировщике»
OpenCode -> LLM: запрос на планирование
LLM -> OpenCode: «Нужно: 1) создать эскиз в Компас-3D, 2) выдавить, 3) экспортировать в DXF, 4) отправить на CarverAll»
OpenCode -> kompas3d-mcp: вызов tool "create_sketch"
kompas3d-mcp -> OpenCode: success
...
OpenCode -> carverall-mcp: вызов tool "start_job"
carverall-mcp -> OpenCode: job_id=42
OpenCode -> Ты: «Готово! Заготовка отправлена, статус можно проверить по ID 42»
```

**Почему мы строим всё на open-source стеке?**
- **Независимость** от вендоров и санкционных ограничений.
- **Низкая стоимость** — DeepSeek стоит копейки (а YandexGPT вообще российский), свои MCP-серверы крутятся локально.
- **Полный контроль** над данными и логикой работы. Ты можешь кастомизировать любой компонент.

## Модуль 0.2 — Знакомство с OpenCode

### 2.1 Что такое OpenCode и зачем он нам

**OpenCode** — это open-source терминальный AI-ассистент с агентной архитектурой. Он живёт прямо в твоём терминале и умеет:
- Общаться с различными LLM-провайдерами (DeepSeek, YandexGPT, OpenAI и др.).
- Выполнять многошаговые планы: модель говорит «сделай A, потом B», а OpenCode сам вызывает инструменты, анализирует результаты и решает, что делать дальше.
- Подключать любые MCP-серверы через стандартный протокол Model Context Protocol — это как универсальный USB для AI-инструментов.

**Чем он отличается от Aider, Claude Code и прочих?**
- OpenSource и полностью настраиваемый (ты не привязан к одному вендору).
- Нативная поддержка MCP из коробки — не нужно писать плагины.
- Работает в терминале и легко встраивается в CI/CD.

В нашем курсе OpenCode будет «мозгом»: он понимает твои производственные задачи, планирует цепочку «спроектировать → вырезать» и последовательно дёргает наши кастомные MCP-серверы.

### 2.2 Установка и первый запуск

Установим OpenCode глобально через npm:
```bash
npm install -g opencode-ai
```
После установки проверь версию:
```bash
opencode --version
# > opencode/1.15.11 linux-x64 node-v22.14.0
```

> **Примечание для Windows:** используй PowerShell от имени администратора, если возникают проблемы с правами. Вместо `opencode` команда может быть `opencode.cmd`.

Теперь попробуем запустить OpenCode:
```bash
opencode
```
Если конфигурация ещё не задана, OpenCode сам предложит настроить провайдера через `/connect`. Выйди пока через Ctrl+C.

Чтобы просто посмотреть доступные команды:
```bash
opencode --help
```
Вывод покажет основные команды и глобальные флаги.

Полезные флаги и команды, которые понадобятся в курсе:
- `--log-level DEBUG` — включает подробное логирование (видно, какие инструменты вызываются, ответы LLM).
- `--print-logs` — выводит логи в stderr (полезно в скриптах).
- `-m, --model <provider/model>` — явно указать модель (например `deepseek/deepseek-chat`).
- `opencode run "запрос"` — запустить в неинтерактивном режиме.

> **💡 Plan mode (Tab):** В TUI OpenCode есть режим планирования. Нажми **Tab** — модель только опишет план действий, не внося изменения. Переключись обратно в `Build` (ещё раз Tab) и подтверди выполнение.

### 2.3 Конфигурация OpenCode (`opencode.json`)

OpenCode настраивается через JSON-файл. Вот минимальная структура для версии 1.15.11:

```json
{
  "$schema": "https://opencode.ai/config.json",
  "model": "deepseek/deepseek-chat",
  "provider": {
    "deepseek": {
      "options": {
        "apiKey": "{env:DEEPSEEK_API_KEY}",
        "baseURL": "https://api.deepseek.com/v1"
      }
    }
  },
  "instructions": ["INSTRUCTIONS.md"],
  "mcp": {}
}
```

**Ключевые поля:**
- `model` — идентификатор модели в формате `provider/model_id` (например, `"deepseek/deepseek-chat"`).
- `provider` — объект, где ключ — имя провайдера (`deepseek`, `anthropic`, `openai` и т.д.).
  - `options.apiKey` — API-ключ (через `{env:VAR_NAME}` для переменных окружения).
  - `options.baseURL` — для self-hosted или кастомных эндпоинтов.
- `instructions` — массив путей к файлам с инструкциями (заменяет `system_prompt`).
- `mcp` — объект конфигураций MCP-серверов (подключим в следующих блоках).

Создадим в папке `opencode-config/` файл `opencode.deepseek.json` с шаблоном:

```json
{
  "$schema": "https://opencode.ai/config.json",
  "model": "deepseek/deepseek-chat",
  "provider": {
    "deepseek": {
      "options": {
        "apiKey": "{env:DEEPSEEK_API_KEY}",
        "baseURL": "https://api.deepseek.com/v1"
      }
    }
  },
  "instructions": ["INSTRUCTIONS.md"],
  "mcp": {}
}
```

Обрати внимание: мы использовали `"{env:DEEPSEEK_API_KEY}"` — OpenCode подставляет переменные окружения на лету. Так ключ не будет светиться в конфиге.

Рядом создадим файл `opencode-config/INSTRUCTIONS.md` с системным промптом:

```markdown
Ты — инженерный AI-ассистент. Твоя задача — помогать проектировать детали и управлять лазерным гравировщиком.
```

Сейчас запустить с этим конфигом не получится, потому что переменная ещё не задана. Мы сделаем это в Модуле 0.3.

## Модуль 0.3 — Получение API-ключей и тестовый прогон

### 3.1 Регистрация в DeepSeek и получение API-ключа

DeepSeek предлагает недорогое API, совместимое с форматом OpenAI. Для наших экспериментов хватит пары центов.

1. Перейди на [https://platform.deepseek.com/](https://platform.deepseek.com/) и зарегистрируйся (можно через Google/GitHub).
2. После входа слева выбери раздел **API Keys**.
3. Нажми **Create new key**, скопируй ключ (начинается с `sk-...`).
4. Проверь баланс в разделе **Billing** — пополни при необходимости. Для тестов хватит 1–2 долларов.

> **Типичная проблема:** Если страница не открывается из РФ, используй VPN. API доступно глобально, но веб-интерфейс может быть заблокирован.

Сохрани ключ временно в безопасное место.

### 3.2 Регистрация в Yandex Cloud и получение доступа к YandexGPT

YandexGPT — это российская модель, доступная через Yandex Cloud. Для работы понадобится IAM-токен или API-ключ сервисного аккаунта. OpenCode не имеет встроенного провайдера YandexGPT, но мы подключим его как кастомный OpenAI-совместимый провайдер.

1. Зайди в [консоль Yandex Cloud](https://console.cloud.yandex.ru/) и создай новый проект (платёжный аккаунт привязывать не обязательно для стартового гранта, но может потребоваться).
2. Перейди в **IAM** → **Service accounts**, создай сервисный аккаунт с именем `ai-engineer`.
3. Назначь роли: `ai.languageModels.user` (для доступа к YandexGPT) и `editor` (для общего управления).
4. В том же сервисном аккаунте выбери **Create API key**, скопируй значение.
5. Убедись, что сервис **YandexGPT API** активирован: в консоли перейди в "Foundation Models" и нажми "Enable".
6. Скопируй **ID каталога** (folder ID) — он понадобится для модели URI. Найти можно на главной странице консоли в карточке каталога или в URL после `/folders/`.

Теперь у тебя есть ключ (выглядит как `AQVN...`) и folder ID.

### 3.3 Безопасное хранение ключей

**Золотое правило:** никогда не коммитить ключи в Git. Мы будем использовать `.env`-файл.

В корне монорепозитория создай файл `.env`:
```env
DEEPSEEK_API_KEY=sk-xxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxx
YANDEX_API_KEY=AQVNxxxxxxxxxxxxxxxx
YANDEX_FOLDER_ID=b1gxxxxxxxxxxxxxxxxxxxxx
```

Сразу проверь, что в `.gitignore` есть строка `.env` (мы добавили её ранее).

Также создай образец `.env.example`:
```env
DEEPSEEK_API_KEY=your_deepseek_key_here
YANDEX_API_KEY=your_yandex_key_here
YANDEX_FOLDER_ID=your_folder_id_here
```
Его можно коммитить — коллеги будут знать, какие переменные нужны.

> **Важно для Windows:** если используешь PowerShell, переменные из `.env` можно загрузить через `Get-Content .env | ForEach-Object { ... }`. Но проще всего — запускать OpenCode в Git Bash.

OpenCode умеет читать `.env` автоматически. Но если переменные не подхватились — экспортируй вручную перед запуском:
```bash
export $(grep -v '^#' .env | xargs)
echo $YANDEX_API_KEY   # должно вывести ключ
```

### 3.4 Настройка OpenCode для DeepSeek и YandexGPT

У нас уже есть конфиг для DeepSeek. YandexGPT не является встроенным провайдером OpenCode, поэтому подключим его через пакет `@ai-sdk/openai-compatible`. Для начала установи его в папку `opencode-config/`:

```bash
cd opencode-config
npm install @ai-sdk/openai-compatible@^2.0.48
cd ..
```

Теперь в папке `opencode-config/` создай `opencode.yandex.json`:

```json
{
  "$schema": "https://opencode.ai/config.json",
  "model": "yandex/gpt://<FOLDER_ID>/yandexgpt/latest",
  "provider": {
    "yandex": {
      "npm": "@ai-sdk/openai-compatible",
      "name": "YandexGPT",
      "options": {
        "baseURL": "https://llm.api.cloud.yandex.net/v1",
        "headers": {
          "Authorization": "Api-Key {env:YANDEX_API_KEY}",
          "x-folder-id": "<FOLDER_ID>"
        }
      },
      "models": {
        "gpt://<FOLDER_ID>/yandexgpt/latest": {
          "name": "YandexGPT"
        }
      }
    }
  },
  "instructions": ["INSTRUCTIONS.md"],
  "mcp": {}
}
```

**Ключевые отличия от встроенного провайдера:**
- `npm`: `"@ai-sdk/openai-compatible"` — указывает OpenCode использовать OpenAI-совместимый адаптер.
- `name`: отображаемое имя провайдера в интерфейсе.
- `options.headers` — YandexGPT использует заголовок `Authorization: Api-Key <ключ>`, а не стандартное `Bearer`. Folder ID передаётся через заголовок `x-folder-id`.
- `models` — объект, где ключ — полный URI модели формата `gpt://<folder_id>/yandexgpt/latest`.
- Модель указывается как `yandex/gpt://<FOLDER_ID>/yandexgpt/latest` (провайдер/модель).
- **Важно:** замени `<FOLDER_ID>` на ID твоего каталога из Yandex Cloud (например, `b1g0935stk09dh1fpn7i`). `{env:YANDEX_API_KEY}` подставляется OpenCode из переменной окружения — экспортируй её или укажи в `.env`.

### 3.5 Тестовый прогон с DeepSeek

Убедись, что файл `.env` существует в корне проекта с `DEEPSEEK_API_KEY`, и выполни:

```bash
OPENCODE_CONFIG=opencode-config/opencode.deepseek.json opencode
```

Откроется интерактивная сессия. Ты увидишь приглашение:

```
🤖 OpenCode (deepseek/deepseek-chat) > _
```

Введи первый запрос:
```
> Привет! Как дела?
```
Ожидаемый ответ (пример):
```
Привет! Я в порядке, готов помогать с проектированием. Что будем создавать?
```

Теперь проверим базовый Function Calling (хотя инструментов ещё нет, модель может просто ответить):
```
> Сколько будет 2+2?
```
Ответ DeepSeek:
```
2 + 2 = 4.
```
Если модель отвечает «4», значит всё работает. Для выхода напиши `exit` или нажми Ctrl+C.

> **Типичные проблемы:**
> - **Ошибка 401 (Unauthorized):** проверь, что API-ключ правильный и указан в `.env`. Используй `echo $DEEPSEEK_API_KEY` для проверки.
> - **Пустой ответ или обрыв связи:** DeepSeek иногда таймаутит при высокой нагрузке. Попробуй ещё раз или проверь сеть/VPN.
> - **Ошибка "Provider not found":** убедись, что провайдер `deepseek` указан в конфиге как ключ объекта `provider`, а не через `"type"`.

### 3.6 Тестовый прогон с YandexGPT

Убедись, что `.env` содержит `YANDEX_API_KEY` и `YANDEX_FOLDER_ID`, и запусти:

```bash
OPENCODE_CONFIG=opencode-config/opencode.yandex.json opencode
```

Введи:
```
> Привет, представься и скажи, на каком языке ты общаешься.
```
YandexGPT ответит что-то вроде:

> - **Ошибка "Permission denied":** сервисному аккаунту не назначена роль `ai.languageModels.user` на каталог. Назначь в консоли Yandex Cloud.

### 🚨 Типичные проблемы и их решения (общий раздел)

| Проблема | Вероятная причина | Решение |
|----------|-------------------|---------|
| `opencode: command not found` | Глобальный npm-путь не в PATH | Перезагрузи терминал, либо добавь `$(npm -g bin)` в PATH. В Windows проверь `%APPDATA%\npm`. |
| Ошибка "Provider not found" | Неверный формат конфига провайдера | В v1.15.11 провайдеры указываются как `"deepseek": { "options": {...} }`, а не через `"type": "deepseek"`. |
| DeepSeek возвращает пустой ответ | Проблемы с сетью или превышена квота | Проверь VPN, баланс в личном кабинете, попробуй позже. |
| YandexGPT не отвечает / "Unknown provider" | Не указан `"npm": "@ai-sdk/openai-compatible"` или пакет не установлен | YandexGPT — кастомный провайдер; добавь `npm` поле в конфиг и выполни `npm install @ai-sdk/openai-compatible` в папке с конфигом. |
| YandexGPT отвечает «Permission denied» | Не включён сервис Foundation Models или нет роли у сервисного аккаунта | Активируй сервис в консоли, добавь роль `ai.languageModels.user` сервисному аккаунту на каталог. |
| YandexGPT «Failed to parse model URI» | Неверный формат model в конфиге | Используй `gpt://{env:YANDEX_FOLDER_ID}/yandexgpt/latest`, а folder_id должен совпадать с каталогом сервисного аккаунта. |
| YandexGPT «Unauthenticated» | Переменная `YANDEX_API_KEY` не загружена | Экспортируй переменные: `export $(grep -v '^#' .env | xargs)`. |
| Ошибка `401 Unauthorized` | Неверный или просроченный ключ | Пересоздай ключ в панели, проверь, что переменная окружения точно загружена (`echo $API_KEY`). |
| Переменные из `.env` не видны | opencode не видит .env в текущей директории | Убедись, что `.env` лежит в корневой директории проекта (где запускаешь opencode). OpenCode v1.15.11 читает .env автоматически. |
