## Модуль 6.1. Архитектура оркестратора и конфигурация OpenCode с MCP-серверами

### Теория

#### Роль оркестратора
Оркестратор — это «дирижёр» ваших инструментов. Он получает высокоуровневую команду на естественном языке (например, «изготовь корпус датчика»), планирует последовательность операций, вызывает нужные инструменты на разных MCP-серверах, агрегирует результаты и ведёт диалог с пользователем для уточнения параметров.

#### Почему OpenCode?
OpenCode — это терминальный AI-ассистент с глубокой нативной поддержкой MCP. Его ключевые преимущества для нашей задачи:

- **Нативная работа с MCP**: достаточно перечислить серверы в конфигурации, и OpenCode сам запустит их как дочерние процессы, установит соединение через `stdio` и получит список инструментов.
- **Автоматический цикл общения с LLM**: вам не нужно реализовывать опрос модели, обработку `tool_calls` и отправку результатов — OpenCode делает это самостоятельно.
- **Гибкая конфигурация**: модель, провайдер, системный промпт, параметры MCP-серверов — всё задаётся в одном JSON-файле.
- **Активное open-source сообщество и прозрачная отладка**.

#### Как OpenCode интегрирует MCP
1. При запуске OpenCode читает файл `opencode.json` (или `opencode.jsonc`) из рабочей директории.
2. Для каждого объекта в `mcp_servers` порождает дочерний процесс с указанной `command` и `args`.
3. Через стандартные потоки ввода/вывода (`stdio`) происходит MCP-рукопожатие: сервер сообщает о своих возможностях, OpenCode получает список инструментов с их именами, описаниями и схемами параметров.
4. Полученные инструменты становятся доступны языковой модели. Когда модель решает вызвать инструмент, OpenCode перенаправляет запрос соответствующему серверу и возвращает результат модели.

**Важное ограничение**: OpenCode полностью контролирует цикл «LLM ↔ инструменты». Вы не можете вмешаться в логику выбора инструментов на лету — только настраиваете поведение через системный промпт и корректируете описания инструментов в MCP-серверах.

### Практика

#### Шаг 1. Создание финального проекта
Перейдите в корневую папку курса или создайте новую:
```bash
mkdir project-orchestrator && cd project-orchestrator
```
Скопируйте скомпилированные MCP-серверы в поддиректории (если они лежат отдельно, можно просто указать относительные пути в конфигурации):
```
project-orchestrator/
├── opencode.json
├── .env
├── kompas3d-mcp/
│   └── dist/index.js    # собранный сервер
└── carverall-mcp/
    └── dist/index.js
```

#### Шаг 2. Конфигурация OpenCode — `opencode.json`
Создайте файл `opencode.json` со следующим содержимым:

```json
{
  "model": "deepseek-chat",
  "provider": "deepseek",
  "system_prompt": "Ты — ассистент-проектировщик с доступом к Компас-3D и лазерному гравировщику. Всегда используй инструменты, если задача требует создания детали или гравировки. Спрашивай уточнения, если параметров недостаточно.",
  "mcp_servers": [
    {
      "name": "kompas3d",
      "command": "node",
      "args": ["./kompas3d-mcp/dist/index.js"]
    },
    {
      "name": "carverall",
      "command": "node",
      "args": ["./carverall-mcp/dist/index.js"]
    }
  ]
}
```

- `model` и `provider` — DeepSeek (можно заменить на другие, поддерживаемые OpenCode).
- `system_prompt` — первая, базовая версия «личности» оркестратора. Мы расширим её в следующих модулях.
- `mcp_servers` — список серверов, которые OpenCode запустит. Пути должны указывать на реально существующие скомпилированные JS-файлы.

#### Шаг 3. Переменные окружения (`.env`)
Создайте `.env` с API-ключом DeepSeek (если не задан глобально):
```
DEEPSEEK_API_KEY=sk-your-deepseek-api-key
```
OpenCode автоматически загружает `.env` из текущей директории. Альтернативно можно указать ключ в конфигурации, но `.env` безопаснее.

#### Шаг 4. Запуск и проверка подключения серверов
Запустите OpenCode с текущей конфигурацией:
```bash
opencode --log-level DEBUG
```
Флаг `--log-level DEBUG` включит подробное логирование. После старта вы должны увидеть в логах что-то подобное:
```
[INFO] Starting MCP server "kompas3d" with command: node ./kompas3d-mcp/dist/index.js
[INFO] MCP server "kompas3d" connected. Tools: create_part, create_sketch, extrude, export_document, ...
[INFO] Starting MCP server "carverall" with command: node ./carverall-mcp/dist/index.js
[INFO] MCP server "carverall" connected. Tools: upload_job, set_laser_params, start_engraving, get_status, ...
```

Внутри интерактивной сессии OpenCode вы можете проверить доступные инструменты командой `/tools` (если она поддерживается вашей версией) или просто начать диалог — модель будет осведомлена об инструментах.

**Возможная команда для отладки:**
```
Ты знаешь какие-нибудь инструменты? Перечисли их.
```
Ответ должен содержать имена инструментов из обоих MCP-серверов.

#### Шаг 5. Настройка детального логирования
Для глубокой отладки используйте переменную окружения:
```bash
DEBUG=opencode:* opencode --log-level DEBUG
```
Это покажет весь обмен сообщениями с LLM, включая содержимое запросов и ответов, вызовы инструментов и полученные результаты.

### Вопросы для самопроверки

2. Каким образом OpenCode узнаёт о существовании и описаниях инструментов MCP-сервера?
3. Где и как OpenCode хранит API-ключ провайдера? Какие способы безопаснее?

### Практическое задание
- Запустите OpenCode с конфигурацией, но намеренно укажите неверный путь к одному из серверов. Зафиксируйте сообщение об ошибке. Затем исправьте путь и убедитесь, что оба сервера успешно подключаются.
- С помощью `DEBUG=opencode:*` найдите в логах этап MCP-рукопожатия (запрос `initialize`, ответ с `capabilities` и запрос `tools/list`).

## Модуль 6.2. Системный промпт оркестратора и сквозной сценарий

### Теория

#### Системный промпт как «личность» оркестратора
Системный промпт — это главный рычаг управления поведением всей системы. Именно в нём вы описываете:
- **Контекст и роли**: кто такой ассистент, какие у него возможности.
- **Правила выбора инструментов**: в каком порядке их вызывать, какие зависимости существуют.
- **Политику обработки неполных данных**: запрашивать уточнения или использовать умолчания.
- **Ограничения и запреты**: например, не пытаться гравировать без загруженного файла, не превышать лимит попыток.

Пример хорошего промпта для нашего сквозного сценария (будет дорабатываться):

```text
Ты — инженер-технолог с доступом к системе автоматизированного проектирования Компас-3D и лазерному гравировальному станку CarverAll 15Pro.

При запросе на изготовление детали действуй по плану:
1. Создай деталь с указанными размерами и особенностями (отверстия, текст).
2. Экспортируй чертёж в формат DXF.
3. Загрузи DXF в гравировщик, укажи материал и толщину.
4. Установи оптимальные параметры лазера (мощность 50%, скорость 80 мм/с, 1 проход для алюминия; для оргстекла мощность 30%, скорость 100 мм/с, 2 прохода).
5. Запусти гравировку и дождись завершения.

Если какие-то параметры не указаны, используй стандартные значения, но обязательно предупреди пользователя об этом.

При ошибках не повторяй тот же вызов, проанализируй причину и предложи решение.
```

#### Планирование и свобода модели
Языковая модель сама решает, в каком порядке и какие именно инструменты вызывать, опираясь на их описания и ваш системный промпт. Вы не задаёте жёсткий алгоритм, а описываете **намерение** и **ограничения**. Это даёт гибкость: если появится новый инструмент, модель сможет включить его в цепочку без переписывания кода оркестратора.

#### Отладка выбора инструментов
Если оркестратор вызывает не те инструменты или в неверной последовательности, проблема может быть:
- В **описаниях инструментов** (в MCP-серверах) — они недостаточно конкретны или двусмысленны.
- В **системном промпте** — инструкции противоречивы или неполны.

Корректируйте именно эти два места, а не пытайтесь управлять поведением через внешний код.

### Практика

#### Подготовка: запуск эмуляторов
Перед началом работы с OpenCode необходимо запустить эмуляторы Компас-3D и гравировщика. Убедитесь, что они слушают свои порты (по умолчанию из Блоков 4 и 5). Можно использовать скрипт `start-emulators.sh`:
```bash
#!/bin/bash
node ./kompas3d-mcp/emulator.js &
node ./carverall-mcp/emulator.js &
wait
```
Или через `docker-compose`, если образы подготовлены. Главное — чтобы MCP-серверы могли достучаться до эмуляторов.

#### Сквозной сценарий 1: Простая деталь
Запустите OpenCode и выполните запрос:

```
Создай куб 10×10×10 мм и сохрани в STEP.
```

**Ожидаемое поведение (verbose-лог):**
1. OpenCode отправляет запрос к DeepSeek с системным промптом и списком инструментов.
2. Модель возвращает `tool_calls`: например, `kompas3d.create_part({"name": "Куб", "material": "Сталь"})`.
3. OpenCode вызывает сервер, получает `partId`.
4. Следующий шаг: `create_sketch` с plane, `extrude` на 10 мм.
5. Далее `export_document` с форматом STEP.
6. Финальный ответ модели: «Куб 10×10×10 мм создан и сохранён в cube.step».

Проследите всю цепочку в логах, убедитесь, что файл действительно создался в эмуляторе (например, в папке `emulator-output`).

#### Сквозной сценарий 2: Шильдик с гравировкой
Теперь сложный производственный заказ:

```
Спроектируй шильдик 50×20 мм с текстом "Отдел А", выгравируй на алюминии толщиной 0.5 мм.
```

**План, который должна реализовать модель:**
1. Создать деталь-пластину 50×20 мм (через `create_part`, `create_sketch` с прямоугольником, `extrude` на 0.5 мм? Толщина задана материалом, но в САПР обычно выдавливают на толщину заготовки. Можно принять упрощение: создаём прямоугольник и экструдируем на 0.5 мм).
2. Добавить текст "Отдел А" (в эмуляторе Компас это может быть отдельный инструмент `create_text` или `add_engraving_text` — зависит от вашей реализации). Предположим, что в вашем `kompas3d-mcp` есть инструмент `add_text_to_sketch`.
3. Экспортировать в DXF (формат для гравировки).
4. В гравировщике: `carverall.upload_job` с путём к DXF.
5. `set_laser_params` с мощностью 50%, скоростью 80 мм/с, 1 проход.
6. `start_engraving` и периодический опрос `get_status` до статуса `COMPLETED`.

**Наблюдение:** если модель пропускает шаг экспорта в DXF или пытается гравировать сразу STEP, доработайте системный промпт, явно указав: «Перед загрузкой в гравировщик обязательно экспортируй деталь в DXF».

Вот пример успешного диалога в терминале OpenCode:

```
Вы: Спроектируй шильдик 50×20 мм с текстом "Отдел А", выгравируй на алюминии толщиной 0.5 мм.
Ассистент: Принято. Создаю деталь...
[вызов kompas3d.create_part]
[вызов kompas3d.create_sketch]
[вызов kompas3d.add_text_to_sketch]
[вызов kompas3d.extrude]
[вызов kompas3d.export_document]
Деталь экспортирована в /output/shildik.dxf
Загружаю файл в гравировщик...
[вызов carverall.upload_job]
Устанавливаю параметры: мощность 50%, скорость 80 мм/с...
[вызов carverall.set_laser_params]
Запускаю гравировку...
[вызов carverall.start_engraving]
Ожидание завершения...
[вызов carverall.get_status]
Гравировка завершена. Шильдик готов.
```

## Модуль 6.3. Параллельные вызовы, обработка ошибок и финальная демонстрация

### Теория

#### Параллельные вызовы инструментов
Некоторые модели (включая DeepSeek) поддерживают отправку нескольких независимых `tool_calls` в одном ответе. OpenCode умеет обрабатывать такие случаи: он запускает инструменты параллельно и возвращает модели агрегированный результат. Это особенно полезно, когда:
- Нужно одновременно получить статус нескольких подсистем.
- Одна операция не зависит от результата другой (например, запросить список деталей в Компас и статус гравировщика).

OpenCode не гарантирует порядок выполнения параллельных вызовов, но гарантирует, что все результаты будут собраны перед следующим шагом LLM.

#### Обработка ошибок
Ошибки в MCP-инструментах не должны «ронять» оркестратор. OpenCode перехватывает ошибку, возвращает модели сообщение об ошибке, и модель решает, как действовать дальше. Вы можете управлять этим поведением через системный промпт:
```text
Если инструмент вернул ошибку, проанализируй её текст. Если ошибка связана с недоступностью сервера, предложи пользователю проверить подключение. Если ошибка в параметрах, запроси корректные значения. Никогда не вызывай тот же инструмент с теми же параметрами повторно без изменений.
```

Также в конфигурации OpenCode можно задать глобальный `tool_timeout` (в миллисекундах), чтобы не ждать зависший сервер бесконечно. На момент написания этого блока параметр `tool_timeout` добавляется в `opencode.json` на верхнем уровне:
```json
{
  "tool_timeout": 15000,
  ...
}
```
Если инструмент не отвечает дольше указанного времени, OpenCode вернёт модели ошибку тайм-аута.

#### Стратегия fallback
Хороший оркестратор должен быть устойчив к сбоям отдельных компонентов:
- Если один MCP-сервер не запускается, оркестратор может продолжать работу с оставшимися.
- При отсутствии эмулятора гравировщика он может сообщить пользователю и предложить смоделировать результат «вхолостую» (если такая возможность предусмотрена).
- Всегда информируйте пользователя о проблеме и не продолжайте цепочку, если дальнейшие шаги не имеют смысла.

### Практика

#### Сценарий с ошибкой: эмулятор гравировщика недоступен
Остановите эмулятор `carverall` (остановите процесс). Убедитесь, что сам MCP-сервер `carverall-mcp` всё ещё работает (он может стартовать, но не сможет соединиться с эмулятором). Выполните команду:

```
Выгравируй логотип из файла logo.dxf на алюминии.
```

Ожидаемое поведение:
1. Модель вызывает `carverall.upload_job`.
2. Сервер пытается обратиться к эмулятору и возвращает ошибку (например, `ECONNREFUSED`).
3. OpenCode передаёт ошибку модели.
4. Модель, следуя системному промпту, сообщает: «Не удалось подключиться к гравировщику. Проверьте, запущен ли станок и доступен ли он по сети».
5. Цепочка прерывается, оркестратор не пытается запустить гравировку.

#### Сценарий с параллельными запросами
При работающих обоих эмуляторах выполните запрос:

```
Проверь статус гравировщика и список активных деталей в Компас.
```

Если ваша версия DeepSeek и OpenCode поддерживают параллельные вызовы, в логах вы увидите, что модель отправила два `tool_calls` в одном ответе: `carverall.get_status` и `kompas3d.list_parts`. OpenCode выполнит их одновременно и вернёт сводку.

Пример ответа ассистента:
```
Статус гравировщика: IDLE (свободен).
Активные детали в Компас: Куб, Шильдик_Отдел_А.
```

#### Тюнинг промпта для обработки ошибок
Добавим в `system_prompt` конкретные инструкции:
```text
При обработке ошибок:
- Если ошибка содержит "ECONNREFUSED" или "станок недоступен", сообщи пользователю и не продолжай операции с этим оборудованием.
- Если ошибка валидации параметров, выведи список допустимых значений и спроси, что выбрать.
- Если инструмент не отвечает более 15 секунд, считай его недоступным и сообщи пользователю.
- Не пытайся повторить неудачный вызов более 2 раз.
```

## Типичные ошибки и их решение

| Ошибка | Вероятная причина | Решение |
|--------|-------------------|---------|
| **OpenCode не видит инструменты** | Неправильные пути к JS-файлам MCP-серверов или серверы не компилированы. | Проверьте, что `dist/index.js` существует и является точкой входа. Запустите сервер вручную: `node ./kompas3d-mcp/dist/index.js` — должно установиться stdio-соединение без ошибок. |
| **Модель циклит вызовы одного инструмента** | Неправильный результат инструмента заставляет модель думать, что операция не выполнена; либо инструмент возвращает пустой/неверный ответ. | Проверьте, что эмулятор возвращает корректный статус. Добавьте в промпт: «Если инструмент вернул тот же результат, что и в предыдущий раз, остановись и сообщи пользователю». |
| **Ошибка `ECONNREFUSED` при вызове гравировщика** | Эмулятор гравировщика не запущен или запущен на другом порту. | Убедитесь, что эмулятор запущен и адрес в MCP-сервере совпадает. Проверьте переменную окружения `CARVERALL_EMULATOR_URL`. |
| **OpenCode не запускает MCP-сервер (ошибка spawn)** | Не указан `node` в `command`, или `node` нет в PATH. | Всегда используйте `"command": "node"`, а в `args` передавайте путь к скрипту. Альтернативно можно указать `"command": "/usr/local/bin/node"`. |
| **Системный промпт игнорируется** | Промпт переопределён в другом месте (например, через флаги запуска). | Проверьте, что вы не передаёте `--system-prompt` в CLI, если используете файл конфигурации. |
| **Инструменты из одного сервера работают, из другого — нет** | Сервер не может подключиться к своему эмулятору, но MCP-рукопожатие прошло. | Ищите ошибки в логах MCP-сервера. Запустите его отдельно с `DEBUG=mcp:*` и проверьте вызовы к эмулятору. |
| **Долгая пауза без ответа при параллельных вызовах** | Модель отправила несколько tool_calls, но один из серверов завис. | Установите `tool_timeout` в конфигурации OpenCode, чтобы не ждать бесконечно. |
| **Ошибка `tool_timeout` не поддерживается** | Возможно, ваша версия OpenCode ещё не имеет этого параметра. | Обновите OpenCode до последней версии: `npm update -g @opencode/opencode`. |
